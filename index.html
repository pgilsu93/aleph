03 / 접근 방식과 경험 근거

01 문제가 생긴 이유부터 살펴봅니다

화면에 드러난 증상만으로 판단하지 않고, 문제가 생긴 과정과 조건을 함께 살펴봅니다.

경험 근거 · 웹 개발에서 요청과 데이터 흐름을 따라 오류 원인을 확인하고, 수정 후 관련 기능을 점검했습니다.

02 생각을 구현과 비교로 확인합니다

떠오른 설명을 바로 결론으로 삼기보다, 직접 구현하고 결과를 비교해 판단할 근거를 마련합니다.

경험 근거 · 데이터사이언스 석사과정에서 로그 이상탐지 방법을 연구하고, 여러 접근을 비교했습니다.

03 기술이 쓰이는 맥락을 생각합니다

기능이나 분석 결과가 누구에게 필요하고, 어떤 문제를 줄이는지까지 생각하려 합니다.

경험 근거 · 사용자 요청을 화면과 기능에 반영한 경험을 바탕으로, 기술을 실제 사용 맥락과 연결해 봅니다.

BACKGROUND / 두 경험이 이어진 지점

기능이 작동하는 이유에서, 데이터가 말하는 이유까지.

웹 개발에서는 실제로 사용되는 서비스를 다뤘습니다. 사용자 요청을 화면과 기능에 반영하고, 운영 중 발생한 문제의 원인을 확인했습니다. 한 부분을 고치는 일이 다른 기능에 어떤 영향을 주는지도 함께 살펴야 했습니다.

데이터사이언스를 공부하며 질문의 대상이 넓어졌습니다. 어떤 데이터를 정상으로 볼지, 이상이라고 판단할 근거는 무엇인지 살펴보고, 서로 다른 방법을 구현해 결과를 비교했습니다. 결과의 차이를 확인하고 그 이유를 살펴보는 과정이 중요했습니다.

두 경험을 연결하는 기준은 같습니다. 상황을 먼저 이해하고, 생각을 구현과 비교로 확인하며, 결과가 어떤 문제를 설명하는지 정리하는 것. 앞으로도 개발과 분석을 함께 활용해 실제 문제를 다루고 싶습니다.
