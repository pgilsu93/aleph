01 · 로그 이상탐지 연구

시간 정보를 더하면
탐지가 달라질까

로그 그래프의 연결 방식과 시간 정보를 비교한 석사 연구

웹 시스템을 유지보수할 때 운영 문제를 추적하며 로그를 자주 확인했습니다. 이후 데이터사이언스 석사과정에 진학하면서 이전 개발 경험과 AI를 연결할 수 있는 주제로 로그 이상탐지를 선택했습니다.

기존 로그 그래프에 시간 정보를 반영했을 때 이상탐지 성능이 달라지는지 확인하기 위해 가까운 시간에 발생한 로그 관계에 가중치를 주는 방법, 로그 발생 집중도를 반영하는 방법, 일부 연결만 유지하는 Top-k 방식 등을 비교했습니다.

하나의 데이터에서 얻은 결과만으로 방법의 효과를 판단하지 않기 위해 BGL, Thunderbird, HDFS에서 각각 실험했습니다. 개별 방법뿐 아니라 여러 방법을 함께 적용한 경우도 확인했습니다.

시간 가중치를 적용한 경우에는 세 데이터셋 모두에서 F1이 개선됐습니다. 하지만 가장 높은 결과를 보인 방법은 데이터마다 달랐고, 여러 방법을 함께 적용했을 때 오히려 개별 방법보다 성능이 낮아지는 경우도 있었습니다.

02 · 웹 시스템 유지보수

보이는 현상에서
원인까지 따라가기

운영 시스템의 요청 반영과 오류 원인 추적

웹 시스템 유지보수 업무에서 화면 수정, Java 기반 처리 로직 수정, SQL을 이용한 데이터 조회와 처리, 운영 오류 확인을 담당했습니다.

사용자가 보는 화면에서 문제가 발생하더라도 실제 원인은 화면 코드가 아니라 서버의 처리 과정이나 데이터에 있을 수 있었습니다. 그래서 화면만 수정하기보다 요청이 어떤 로직과 SQL을 거치는지 함께 확인했습니다.

오류가 발생했을 때는 애플리케이션 로그와 요청 처리 흐름을 따라가며 원인을 좁혔습니다. 변경 후에는 요청한 기능이 정상적으로 동작하는지만 보는 것이 아니라, 같은 로직이나 데이터와 연결된 다른 기능도 확인했습니다.

이 경험을 통해 화면에 나타난 현상을 하나의 지점으로만 보지 않고 화면, 서버 로직, SQL, 데이터가 연결된 흐름으로 확인하는 방식 을 익혔습니다.
